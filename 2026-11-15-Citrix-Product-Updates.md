# Citrix Product Updates
*Last 24 hours — 2026-11-15*

## NetScaler

### NetScaler Kubernetes Gateway Controller 2.3.0

- **MCP Gateway (published Nov 14, 2026):** The Gateway Controller can now run as a Model Context Protocol (MCP) gateway. It routes, secures and scales generative-AI MCP workloads inside Kubernetes. ([Release 2.3.0 notes](https://docs.netscaler.com/en-us/netscaler-kubernetes-gateway-controller/release-notes/release-notes-2-3-0.html))
- **Gateway API TLSRoute support (published Nov 14, 2026):** The controller now handles the Kubernetes Gateway API `TLSRoute` resource. In Passthrough mode it routes encrypted traffic by SNI host name. In Terminate mode, the default, NetScaler ends TLS with the Gateway certificate and routes requests by the Host header. ([Release 2.3.0 notes](https://docs.netscaler.com/en-us/netscaler-kubernetes-gateway-controller/release-notes/release-notes-2-3-0.html))
- **GSLB for Gateway API routes (published Nov 14, 2026):** The GSLB Controller can now create global load-balancing entries for apps exposed through an `HTTPRoute`. You point a `GlobalTrafficPolicy` host at the route with `routeRef`. This is on by default through the `gatewayAPI.enabled` Helm value. ([Release 2.3.0 notes](https://docs.netscaler.com/en-us/netscaler-kubernetes-gateway-controller/release-notes/release-notes-2-3-0.html))
- **Rotated credentials reload without a restart (published Nov 14, 2026):** This opt-in feature, turned on with `vaultCredentials.enabled`, lets the controller pick up rotated NetScaler credentials, for example from Vault, without restarting the pod. Known issue: a metrics exporter you run separately reads its credential files only at startup, so you must restart it after each rotation. ([Release 2.3.0 notes](https://docs.netscaler.com/en-us/netscaler-kubernetes-gateway-controller/release-notes/release-notes-2-3-0.html))
- **Smart annotations for Gateway routes (published Nov 14, 2026):** You can now set NetScaler content switching, load balancing, service group and monitor settings for each Gateway route with annotations. ([Release 2.3.0 notes](https://docs.netscaler.com/en-us/netscaler-kubernetes-gateway-controller/release-notes/release-notes-2-3-0.html))

### NetScaler Ingress Controller / GSLB Controller 4.3.22 and IPAM Controller 2.5.2

- **New NSIC/GSLB 4.3.22 and IPAM Controller 2.5.2 releases (published Nov 14, 2026):** The release-notes index now lists NetScaler Ingress Controller and GSLB Controller 4.3.22, the matching Helm charts, and IPAM Controller 2.5.2. The detailed notes are on GitHub. ([Release notes index](https://docs.netscaler.com/en-us/netscaler-k8s-ingress-controller/index/release-notes.html), [NSIC 4.3.22 on GitHub](https://github.com/netscaler/netscaler-k8s-ingress-controller/releases/tag/4.3.22), [IPAM 2.5.2 Helm chart](https://github.com/netscaler/netscaler-helm-charts/releases/tag/ipam-v2.5.2))

### NetScaler Operator 3.7.5

- **Rotated-credential hot reload for all controllers (published Nov 14, 2026):** The ingress, gateway, GSLB and node controllers can now pick up rotated credentials from a Vault Agent sidecar. They check for new files every 30 seconds by default and test-log in with a new password before switching to it. This is opt-in through `vaultCredentials.enabled` on each custom resource. ([Operator 3.7.5 notes](https://docs.netscaler.com/en-us/netscaler-k8s-ingress-controller/netscaler-operator-overview/operator-release-notes/release-3-7-5.html))
- **Preconfigured certkeybundle in the Listener CRD (published Nov 14, 2026):** Setting `preconfiguredBundle: true` lets a Listener bind an SSL certkeybundle that already exists on NetScaler. Gateway and Secret-based bundles already worked this way. ([Operator 3.7.5 notes](https://docs.netscaler.com/en-us/netscaler-k8s-ingress-controller/netscaler-operator-overview/operator-release-notes/release-3-7-5.html))
- **TLS settings for the GSLB HTTPS monitor (published Nov 14, 2026):** In a `GlobalTrafficPolicy`, HTTPS health checks now accept optional `sslProfile` and `ciphers` fields. You can set the TLS version, cipher suites and other SSL settings instead of relying on fixed defaults. ([Operator 3.7.5 notes](https://docs.netscaler.com/en-us/netscaler-k8s-ingress-controller/netscaler-operator-overview/operator-release-notes/release-3-7-5.html))
- **Full GSLB monitor tuning (published Nov 14, 2026):** The GSLB health monitor now exposes common fields such as interval, response timeout and retries. An `advancedOptions` map passes through any other NetScaler monitor parameter. ([Operator 3.7.5 notes](https://docs.netscaler.com/en-us/netscaler-k8s-ingress-controller/netscaler-operator-overview/operator-release-notes/release-3-7-5.html))
- **GSLB for Gateway API routes (published Nov 14, 2026):** The operator-managed GSLB Controller can create GSLB entries for `HTTPRoute`-exposed apps through `routeRef`. This is controlled by `gatewayAPI.enabled` on the `NetscalerGslbController` resource. ([Operator 3.7.5 notes](https://docs.netscaler.com/en-us/netscaler-k8s-ingress-controller/netscaler-operator-overview/operator-release-notes/release-3-7-5.html))
- **MCP Gateway with new CRDs (published Nov 14, 2026):** NetScaler can act as an MCP gateway. Traffic is defined with a new `mcproute` CRD and protected with OAuth and token-claim authorization (`authpolicy`). MCP server access control uses `rewritepolicy`, and per-tool rate limiting uses `ratelimit`. ([Operator 3.7.5 notes](https://docs.netscaler.com/en-us/netscaler-k8s-ingress-controller/netscaler-operator-overview/operator-release-notes/release-3-7-5.html))
- **Gateway API TLSRoute support (published Nov 14, 2026):** Operator deployments of the Gateway Controller support `TLSRoute` in both passthrough and terminate modes. ([Operator 3.7.5 notes](https://docs.netscaler.com/en-us/netscaler-k8s-ingress-controller/netscaler-operator-overview/operator-release-notes/release-3-7-5.html))
- **Smart annotations for Gateway routes (published Nov 14, 2026):** You can set load balancing, content switching, service group and monitor settings for each route with annotations. ([Operator 3.7.5 notes](https://docs.netscaler.com/en-us/netscaler-k8s-ingress-controller/netscaler-operator-overview/operator-release-notes/release-3-7-5.html))
- **IPAM queues requests when the pool runs out (published Nov 14, 2026):** Before, a VIP request hung without any feedback when the pool was empty. Now it waits and gets an address as soon as one is freed. Progress shows in Kubernetes events and in a new `Pending`/`Allocated` status on the `vip` resource. ([Operator 3.7.5 notes](https://docs.netscaler.com/en-us/netscaler-k8s-ingress-controller/netscaler-operator-overview/operator-release-notes/release-3-7-5.html))
- **Matches the 4.3.22 Helm charts (published Nov 14, 2026):** The operator's custom resources now offer the same features as the 4.3.22 charts. These include Splunk analytics and tracing, control over service-status publishing, IPAM TLS verification and Node Controller health probes. The operator also sets default CPU and memory for the Gateway Controller and CPX containers. ([Operator 3.7.5 notes](https://docs.netscaler.com/en-us/netscaler-k8s-ingress-controller/netscaler-operator-overview/operator-release-notes/release-3-7-5.html))
- **Metrics exporter certificate validation setting (published Nov 14, 2026):** A new `exporter.validateCert` field controls whether the metrics exporter checks the NetScaler certificate. It defaults to `no`, so upgrades don't change existing behavior. Setting it to `auto` turns validation on and needs exporter 1.7.0 or later. ([Operator 3.7.5 notes](https://docs.netscaler.com/en-us/netscaler-k8s-ingress-controller/netscaler-operator-overview/operator-release-notes/release-3-7-5.html))
- **IPAM status on the vip resource and safer upgrades (published Nov 14, 2026):** The IPAM controller now adds Status and Message columns to each `vip`. It upgrades with the Recreate strategy, so two IPAM pods can no longer hand out the same address during an upgrade. ([Operator 3.7.5 notes](https://docs.netscaler.com/en-us/netscaler-k8s-ingress-controller/netscaler-operator-overview/operator-release-notes/release-3-7-5.html))
- **Deploy the Node Controller through the operator (published Nov 14, 2026):** A new `NetscalerNodeController` custom resource deploys the Node Controller with health probes on by default. On deletion, the operator removes components in an order that lets the overlay config and node routes be cleaned up. ([Operator 3.7.5 notes](https://docs.netscaler.com/en-us/netscaler-k8s-ingress-controller/netscaler-operator-overview/operator-release-notes/release-3-7-5.html))
- **Behavior changes to check before upgrading (published Nov 14, 2026):** Infoblox TLS certificate verification is now on by default for IPAM, so self-signed or private-CA servers need a CA bundle secret. The GSLB controller now deletes GSEs for targets that are no longer in use, unless you set `gseAutoCreation: false`. The operator's default memory limit is raised to 1Gi to prevent OOM crash loops. ([Operator 3.7.5 notes](https://docs.netscaler.com/en-us/netscaler-k8s-ingress-controller/netscaler-operator-overview/operator-release-notes/release-3-7-5.html))
- **Fixed issues (published Nov 14, 2026):** This release has about 20 fixes. They cover duplicate or orphaned NetScaler objects after operator upgrades, Calico PBR routes overwriting each other, VIPs not surviving CPX restarts with persisted configuration, GSLB CPU saturation at scale, and multicluster SSL-passthrough naming collisions. ([Operator 3.7.5 notes](https://docs.netscaler.com/en-us/netscaler-k8s-ingress-controller/netscaler-operator-overview/operator-release-notes/release-3-7-5.html))
