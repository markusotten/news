# Skill defects

Defects in the `citrix-product-update` skill and the sources it depends on. This file is the only place they are recorded — the daily and weekly notes never carry a Skill-Bug section.

Each entry has a stable id. Runs update `Last seen` for defects that still occur and move cleared ones to Resolved.

## Open

### phase4-cache-hash-scheme-unreproducible — this run's What's New extraction cannot be reconciled against `.whatsnew-cache.json`
- First seen: 2026-08-16
- Last seen: 2026-08-16
- Expected: re-fetching a product's what's-new page and hashing (heading + first body line) should overlap heavily with the hashes already stored in the cache from the 2026-08-14/2026-08-15 seeding run, so only genuinely new entries surface as "new".
- Actual: built an HTML extractor (curl + stdlib `html.parser`, scoped to the `content-right-wrapper` container) and ran it against all 46 fetchable catalog products. Overlap with the existing cache was 0 out of 0 on every single product, and entry counts were often implausibly high (e.g. 1606 raw entries on Citrix DaaS, 574 on Citrix Enterprise Browser) — a strong sign the extraction boundaries or heading/body splitting differ from whatever the seeding run used, not that every page changed simultaneously. `docs.netscaler.com` pages additionally returned 0 entries because they don't use the same `content-right-wrapper` class as `docs.citrix.com`.
- Run did: did **not** report any entries from this pass to avoid flooding the daily note with years-old content misreported as new, and did **not** overwrite `.whatsnew-cache.json` (to avoid destroying the working baseline other runs may still be able to diff against). As a cache-independent fallback, checked every extracted entry's date context for exact day-level dates (not just month-level) falling inside this run's window (2026-08-15T02:30Z–2026-08-16T03:00Z) — none were found on any of the 46 products, so no dated in-window items were missed by this gap. A future run should either locate/reuse the exact extraction script from the 2026-08-14/2026-08-15 seeding run, or deliberately re-seed the cache with a documented, stable method and accept one cycle of reduced diff coverage while doing so.

New findings: `Citrix Receiver` and `XenApp and XenDesktop (legacy)` genuinely have no what's-new page → `none` (Receiver's own nav points to Workspace app's page instead). `Session Remote Start` has no reachable what's-new content but isn't ruled out → `unverified:`. `Citrix Secure Hub` resolved to `overview.html#whats-new-in-the-current-version`. `Global App Configuration Service` shares StoreFront Cloud's `citrix-workspace/whats-new.html` (its own landing page's "What's new" link points there). `Citrix App Layering`, `Session Recording Service`, `Citrix Secure Private Access` and `Unicon eLux Scout` confirmed as `unverified:` per the prior run's finding (numbered doc-set page, service-overview redirect, legacy-archive page, and a versioned `2607/` folder respectively — the last does contain valid content today but is unstable across releases). All other resolutions from the 2026-08-13/2026-08-14 research reconfirmed unchanged.
