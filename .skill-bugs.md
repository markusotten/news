## Open

### github-org-repos-scoped — GitHub access blocked by session proxy for non-`markusotten/news` repos
- First seen: 2026-08-13
- Last seen: 2026-08-13
- Expected: `GET https://api.github.com/orgs/citrix/repos?sort=pushed` returns the org's repos so Phase 6 can spot new/updated Citrix GitHub repos; failing that, the skill's documented workaround — plain `curl` against each watchlist repo's `https://github.com/<owner>/<repo>/releases.atom` and `/tags.atom` — should work since those are plain `github.com` URLs, not `api.github.com`.
- Actual: Both routes are blocked with the same error. `api.github.com` org listing is rejected outright. As of this run, the Atom-feed workaround is *also* blocked: `curl` against `https://github.com/<owner>/<repo>/releases.atom` for every one of the 8 GitHub watchlist repos (tested `citrix/terraform-provider-citrix`, `citrix/citrix-k8s-ingress-controller`, `netscaler/netscaler-k8s-ingress-controller`, `xenserver/xenadmin`) returns HTTP 403 with `{"message":"This GitHub API path is not available: sessions are bound to their configured repositories. Use repository-scoped endpoints (repos/{owner}/{repo}/...)."}` — the session's GitHub proxy scopes *all* github.com access to `markusotten/news`, not just the REST API.
- Run did: skipped the GitHub-repos portion of Phase 6 entirely (no releases/tags could be checked for any of the 8 watchlist repos); everything else in Phase 6 (Tech Zone articles/blogs, community events, YouTube) completed normally via `curl`.

- Last seen: 2026-08-13
- Expected: Phase 4 fetches the What's New / release-notes page for all 61 products in `citrix-produts.md` every run.
- Actual: Two runs today have now sampled rather than exhaustively swept, because each run's window has been under two hours. The earlier same-day run checked ~14 products (Citrix Virtual Apps and Desktops, Citrix DaaS, Citrix Workspace app for Windows, NetScaler Console service, NetScaler ADC, NetScaler Console, Client app management, LAS for NetScaler, Citrix Secure Private Access, Citrix Provisioning, Citrix Cloud, and others). Full 61-product coverage should resume once a run gets a normal (multi-hour/24h) window, since a short-window run cannot fetch all 61 product pages and still finish promptly.

### catalog-missing-whatsnew-column — `citrix-produts.md` lacks the dedicated What's New URL column the skill requires
- First seen: 2026-08-13
- Last seen: 2026-08-13
- Expected: Per the skill, `citrix-produts.md` should hold "both the docs URL and the product's 'what's new' / release-notes URL" as two columns, so Phase 4 never has to rediscover the release-notes URL for a product.
- Actual: The file as built today (Phase 3 bootstrap) has only a single `Docs URL` column. Phase 4 has been working around this by guessing a `/whats-new` (or `/whats-new.html`) suffix on the docs URL, which happens to resolve for the docs.citrix.com and docs.xenserver.com products tried so far, at the cost of an extra fetch per product (one to discover the link, one to read it) instead of one.
- Run did: continued using the guessed-suffix workaround rather than restructuring the 61-row table under a short window; the table should get a second column added on a future run with enough budget to resolve and verify all 61 what's-new URLs.
